## What we stand for

<CardGrid>
  <Card title="One ecosystem">
    Every X-app is built on the same libraries, the same design and the same architecture, so the apps look alike, behave alike and talk to each other. A fix or a feature in the shared layer reaches every app at once, and learning one app teaches you the rest.
  </Card>
  <Card title="Extensible, configurable, interoperable">
    Apps adapt to their users, not the other way round: plugins, settings, themes and layouts, built on open formats and standard protocols so they work with other tools. Every app has an API and an MCP server, so scripts, other apps and AI agents can use it too. When people want different things, the answer is a plugin or a setting, not a fork.
  </Card>
  <Card title="The best of what exists">
    Each app starts from the products people already use, open source or not, and brings their best features together. It imports their data and connects to them where it can, so switching costs nothing and nothing is left behind.
  </Card>
  <Card title="Built with AI, held to tests">
    AI is what lets a small team, or one person, build a whole ecosystem. It is used in the open: disclosed, reviewed and guided by each project's `AGENTS.md`. CI/CD and tests carry the routine load, and every change must pass them.
  </Card>
</CardGrid>

## Principles

1. **People stay accountable.** Whoever submits a change owns it, however it was written.
2. **Be open about the tools.** Disclosure is normal and expected, never a mark against a contribution.
3. **Tests before trust.** Code is accepted because it is verified, not because of who or what wrote it.
4. **Readable by people.** All code stays simple enough for a person to review and maintain without AI.
5. **Respect licences and upstreams.** Credit the products and projects we learn from and build on, and follow their licences.
6. **Lighten the load on maintainers.** Automation and AI should reduce the work of reviewing contributions, not add to it.
7. **Share before you build.** A feature two apps could use goes in the shared libraries, and an idea that fits an existing app becomes a feature, setting or plugin there instead of a new app.
8. **Extend, don't fork.** Settle differences with plugins, settings and open formats, so one app can serve many needs.
9. **Share what works.** The apps, libraries, guidelines and tooling we build are all free software.
