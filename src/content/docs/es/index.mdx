## Lo que defendemos

<CardGrid>
  <Card title="Un solo ecosistema">
    Cada X-app se construye sobre las mismas bibliotecas, el mismo diseño y la misma arquitectura, así que las aplicaciones se parecen, se comportan igual y se comunican entre sí. Una corrección o una función en la capa compartida llega a todas las aplicaciones a la vez, y aprender a usar una enseña a usar las demás.
  </Card>
  <Card title="Extensible, configurable, interoperable">
    Las aplicaciones se adaptan a quienes las usan, y no al revés: plugins, ajustes, temas y diseños, construidos sobre formatos abiertos y protocolos estándar para que funcionen con otras herramientas. Cada aplicación tiene una API y un servidor MCP, para que los scripts, otras aplicaciones y los agentes de IA también puedan usarla. Cuando la gente quiere cosas distintas, la respuesta es un plugin o un ajuste, no una bifurcación.
  </Card>
  <Card title="Lo mejor de lo que ya existe">
    Cada aplicación parte de los productos que la gente ya usa, sean de código abierto o no, y reúne sus mejores funciones. Importa sus datos y se conecta con ellos cuando puede, para que cambiar no cueste nada y no se pierda nada por el camino.
  </Card>
  <Card title="Hecho con IA, sujeto a pruebas">
    La IA es lo que permite que un equipo pequeño, o una sola persona, construya un ecosistema entero. Se usa abiertamente: declarada, revisada y guiada por el `AGENTS.md` de cada proyecto. La CI/CD y las pruebas llevan la carga rutinaria, y todo cambio debe superarlas.
  </Card>
</CardGrid>

## Principios

1. **Las personas siguen siendo responsables.** Quien envía un cambio es su dueño, se haya escrito como se haya escrito.
2. **Sé transparente con las herramientas.** Declararlas es normal y esperado, nunca una marca en contra de una contribución.
3. **Pruebas antes que confianza.** El código se acepta porque está verificado, no por quién o qué lo escribió.
4. **Legible por personas.** Todo el código se mantiene lo bastante sencillo para que una persona pueda revisarlo y mantenerlo sin IA.
5. **Respeta las licencias y los proyectos de origen.** Reconoce a los productos y proyectos de los que aprendemos y sobre los que construimos, y sigue sus licencias.
6. **Aligera la carga de quienes mantienen.** La automatización y la IA deben reducir el trabajo de revisar contribuciones, no aumentarlo.
7. **Comparte antes de construir.** Una función que podrían usar dos aplicaciones va a las bibliotecas compartidas, y una idea que encaja en una aplicación existente se convierte allí en una función, un ajuste o un plugin, en vez de en una aplicación nueva.
8. **Extender, no bifurcar.** Resuelve las diferencias con plugins, ajustes y formatos abiertos, para que una aplicación pueda servir a muchas necesidades.
9. **Comparte lo que funciona.** Las aplicaciones, bibliotecas, guías y herramientas que creamos son todas software libre.
