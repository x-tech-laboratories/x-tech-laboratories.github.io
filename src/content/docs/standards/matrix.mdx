No app yet checks its coverage floor in CI, so Tests + CI is partly met everywhere.

Libraries and components whose host fixes their shape follow only the parts that apply to them, as
the standard's scope sets out, and are left out of the matrix: X-Libs, Halon, RoboBuddy,
ai-readiness, MOSAIC, X-Login and X-Plymouth.

## What each app still lacks

### X-Backups

- Platforms: web only; no desktop or Android app.
- API + MCP: MCP is served, `/api/openapi.json` is not.
- Settings: configuration views, but no `SettingsPage` in the sidebar's foot.
- Sync, History, Plugins, Notifications: not started.

### X-Budget

- Daemon + UI: the desktop app keeps its store in Electron's main process, with no daemon.
- Plugins, Notifications: not started.

### X-Fitness

- Plugins, Notifications: not started.

### X-Media-Tracker

- Daemon + UI: the desktop app keeps its store in Electron's main process, with no daemon.
- Notifications: book alerts go out through ntfy, a webhook and mail; no desktop or phone
  notifications and no Notifications settings section.

### X-Monitor

- Platforms: web only; no desktop or Android app.
- Settings: a sidebar row of its own instead of the sidebar's foot.
- Sync: its own record sync, not the X-Libs sync modules.
- History: an event log, but no `create_history` and no History page.

### X-Music

- Platforms: desktop only, since it plays through `mpv` from local disks, as its README says.
- Daemon + UI: library and playback run in Electron's main process, with no daemon.
- Plugins: planned, not started.
- Notifications: not started.
- Tests + CI: a coverage floor is set, but CI does not run coverage.

### X-Nix

- Platforms: web only; no desktop or Android app.
- API + MCP: MCP is served, `/api/openapi.json` is not.
- Sync, History, Plugins: not started.
- Notifications: sent through ntfy, a webhook and Apprise, with no Notifications settings section.

### X-Stream

- Stack: on older X-Libs and Halon, and also uses PouchDB beside its SQLite store.
- Daemon + UI: work runs in Electron's main process and the page, with no daemon.
- Platforms: desktop only; its README plans a React Native phone app, which the standard does not
  use.
- API + MCP: none.
- History: kept for playlists only.
- Notifications: not started.

### X-Tasks

- API + MCP: its own MCP server on a port of its own, not `api_spec`, and no `/api/openapi.json`.
- Plugins: not started.
- Notifications: desktop and phone notifications work; the server sends none through the X-Libs
  channels, and there is no Notifications settings section.

### CODEX

- Stack: Electron only, with no server.
- Daemon + UI: a daemon on its own socket client, not X-Libs' `local_daemon`.
- Platforms: desktop only.
- API + MCP: uses other programs' MCP tools but offers none of its own.
- Settings: an options view, not a `SettingsPage` in the sidebar's foot.
- Notifications: Electron's own notifications from the main process, not X-Libs' `desktop_notify`
  from the daemon.
- Sync, History, Plugins: not started.
- Branding: the name lacks the `X-` prefix.
