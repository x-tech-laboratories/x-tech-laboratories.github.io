There are often several products that each solve part of the same problem: one is fast, another is
easy to extend, a third has the best data model. Users must pick one and live without the rest. We
would rather bring their strengths together in one place, whether they come from open source
projects or proprietary ones.

## How we do it

1. **Survey the field.** List the competing products and what each does best, and what their users
   would miss if they switched.
2. **Make the best of each a goal.** Write those strengths down as requirements, ideally as tests.
3. **Import everything.** Read the other products' data and settings, so switching keeps a user's
   history, ratings, playlists or configuration. Nobody should start from zero.
4. **Connect to what stays.** Where people keep using another product or service, sync with it
   through its API, an open format or a plugin instead of asking them to give it up.
5. **Make the differences settings.** Where products disagree on how something should behave, offer
   both as options rather than picking a winner.
6. **Credit and respect upstreams.** Say where an idea or a feature comes from, follow the original
   licence for any code you reuse, and send fixes back where it helps.

## Example

[X-Music](/projects/#x-music) keeps gmusicbrowser's library engine and data model, imports an existing
gmusicbrowser library, and puts a modern interface on top that users can re-layout and re-skin.
[X-Media-Tracker](/projects/#x-media-tracker) imports a watch history from Trakt, Stremio and the
Trilium Media Tracker add-on, so nobody starts their library from zero.
